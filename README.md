# Бот с расписанием ИС-41-23к

Каждый вечер присылает в группу расписание на завтра с сайта НФ УУНиТ.
По командам `/today` и `/tm` показывает расписание в любой момент.
Рассылка живёт в GitHub Actions, команды — в вебхуке на Vercel.
Своего сервера не нужно.

| Файл | Что делает |
|---|---|
| `parser.py` | тянет расписание с сайта, отдаёт пары нужной группы |
| `bot.py` | собирает текст сообщения и отправляет в Telegram |
| `merge_state.py` | сливает `state.json`, если его пишут одновременно |
| `homework.py` | ловит «дз!» в чате и напоминает накануне |
| `set_webhook.py` | прописывает адрес вебхука в Telegram |
| `.github/workflows/daily.yml` | вечерняя рассылка |
| `app.py` | вебхук на Vercel: ответы на `/raspisanie` |
| `state.json` | что уже отправлено и на каком сообщении остановились |
| `homework.json` | записи о дз |

## Секреты

Три значения нельзя класть в код — они лежат в настройках репозитория.

**Settings → Secrets and variables → Actions → New repository secret.** Три раза:

| Name | Secret |
|---|---|
| `BOT_TOKEN` | токен от @BotFather, вида `1234567890:AA...` |
| `CHAT_ID` | id группы, у супергрупп с минусом: `-100XXXXXXXXXX` |
| `OWNER_ID` | твой личный id — туда придут сообщения об ошибках |

Имена должны совпадать буква в букву, иначе бот скажет «не задан BOT_TOKEN».

Локально те же три значения лежат в `.env.local` рядом с `bot.py`. Этот файл
в `.gitignore` и на GitHub не уезжает — заполняешь его один раз у себя.

Если не знаешь `CHAT_ID`: добавь бота в группу, напиши там что угодно и открой
`https://api.telegram.org/bot<ТОКЕН>/getUpdates` — id будет в поле `chat.id`.

## Расписание запусков

`daily.yml` — в 13:20, 14:20, 15:20 и 16:20 UTC, то есть 18:20, 19:20, 20:20 и
21:20 по Уфе. Первый запуск, который увидит расписание, отправит его; остальные
промолчат. Последний запуск идёт с флагом `--last`: если расписание к вечеру так
и не выложили, он предупредит об этом и закроет день.

Команды живут **не в Actions, а в вебхуке на Vercel** (`app.py`).
Причина: GitHub не соблюдает крон `*/5` — по факту прогоны случались раз в
несколько часов, и `/raspisanie` висела неотвеченной. Вебхук Telegram зовёт
сразу, ответ приходит за секунду.

Вебхуку нужны те же `BOT_TOKEN`, `CHAT_ID`, `OWNER_ID` плюс `WEBHOOK_SECRET`
— их заводят в настройках проекта Vercel (Environment Variables в боковой
панели проекта), а не в GitHub Secrets. После добавления нужен Redeploy:
к уже собранным деплоям новые переменные не применяются.

Открыв адрес функции в браузере, видно, какие переменные она получила:

```
https://raspisanie-bot.vercel.app/api/telegram
{"ok": true, "note": "...", "env": {"BOT_TOKEN": true, ...}}
```

Прописать адрес вебхука (токен подставится из `.env.local`):

```
.venv\Scripts\python.exe set_webhook.py https://raspisanie-bot.vercel.app/api/telegram
.venv\Scripts\python.exe set_webhook.py --info
```

Команда работает только в группе из `CHAT_ID` и в личке с `OWNER_ID`,
остальные чаты бот игнорирует молча.

```
/today                расписание на сегодня
/tm                   расписание на завтра
/raspisanie 05.09     на конкретную дату
/raspisanie           до 19:00 — на сегодня, после — на завтра
/dz                  домашние задания на ближайшую дату
/help                всё, что умеет бот, и сокращения предметов
```

Подсказки этих команд по кнопке «/» в Telegram ставятся один раз:

```
.venv\Scripts\python.exe set_webhook.py --commands
```

## Домашние задания

Напиши в группе сообщение, которое начинается с **`!дз`** (или `дз!` —
бот понимает оба варианта), дальше предмет и что задали.

### Обычное дз — к ближайшей паре

```
!дз стандартизация работа на юрайте
!дз уфис конспект
```

Бот найдёт ближайший день, когда этот предмет стоит в расписании, и
**вечером накануне** допишет к расписанию:

```
📝 Не забудь сделать дз:
• Стандартизация — стандартизация работа на юрайте
```

### Дз со сроком — например, курсовая на месяц

```
!дз курсовая по уфис до 15.12
!дз курсовая по базам данных до 15 декабря
```

Срок можно писать цифрами (`до 15.12`, `к 15.12.26`, `срок 15.12`) или
словами (`15 декабря`). У цифр нужен предлог — иначе «параграф 5.2»
превратился бы в 5 февраля. За **неделю** до срока бот начнёт напоминать в
каждом сообщении с расписанием, с обратным отсчётом:

```
⏳ Скоро сдавать:
• Устройство и функционирование информационной системы — курсовая по уфис (срок ВТ 15.12, ещё 3 дн.)
```

В сам день срока будет «срок — в этот день ‼️», на следующий день
напоминание пропадёт. Срок, который уже прошёл, бот не запишет и скажет
проверить дату.

Если бот не узнал предмет (и у дз со сроком, и без), он спросит **«По какому
предмету-то дз?»** с двумя кнопками:

* **Нет предмета** — дз запишется без предмета: со сроком — на срок, без
  срока — на ближайший учебный день (выходные бот пропускает);
* **Сейчас напишу** — бот пришлёт сообщение со списком предметов ближайших
  дней, и Telegram сам откроет на него ответ. Пишешь «уфис» — дз встанет на
  ближайшую пару УФИС. Если предмета нет в словаре или в расписании, бот
  возьмёт его как написано и поставит на ближайший учебный день.

* **Отмена** — не записывать это дз вообще. Кнопка остаётся и после
  «Сейчас напишу», если передумал, уже начав отвечать.

Можно и не жать кнопку, а просто ответить на вопрос названием предмета.
Нажимать кнопки и отвечать может только тот, кто написал дз. Вопрос без
ответа через сутки забывается.

### Сколько хранится дз

После даты дз сразу перестаёт показываться в напоминаниях и в `/dz`, а
через **неделю** удаляется из `homework.json` само — на ближайшем
`/today`, `/tm`, `/dz` или любой новой записи, ждать ничего не нужно.

### Удалить дз

```
!дз удалить
!дз удалить уфис
```

Бот покажет записанные дз кнопками — нажатое удалится. С предметом после
«удалить» покажет только дз по этому предмету. Жать кнопки может тот, кто
открыл меню.

Кнопки работают, только если в настройках вебхука разрешены нажатия
(`callback_query`). `set_webhook.py` это делает — после обновления его надо
запустить один раз заново.

### Команда /dz

`/dz` (или `/дз` — набранное вручную бот тоже понимает) показывает дз на
ближайшую дату, **когда оно вообще есть**, — не обязательно на завтра. Ниже
— все задания со сроком. Telegram разрешает в меню команд только латиницу,
поэтому в подсказках по кнопке «/» стоит `/dz`.

### Как бот узнаёт предмет

Таблица `SUBJECTS` в начале `homework.py`: слева название как в расписании,
справа — как ещё его могут написать. Сам бот, без записи в таблицу, понимает:

* **полное название** в любом падеже: «по устройству и функционированию
  информационной системы»;
* **сокращение по первым буквам**: `уфис`, `уабд`, `итпсис`, `попд`, `сстд`,
  `ист`, `вис`, `фк`;
* **отличительное слово** из названия: «сопровождение» — это ИТП, а
  «информационных» — ничего, оно встречается в трёх предметах.

В таблицу нужно дописывать только сленг, который из названия не угадать:

```python
"Физическая культура": [
    "физра", "физ-ра", "физкультура",
],
```

Короткие слова (до 4 букв: «бд», «итп») бот ищет только целиком, длинные —
с любым окончанием.

Если маркер стоит посреди фразы («кто сделал дз! ура»), бот запишет дз,
только когда узнал предмет, а иначе промолчит — чтобы не отвечать на
болтовню. Если сообщение начинается с маркера, а предмет не узнан, бот спросит
предмет кнопками (см. выше).

Дз показывается в вечерней рассылке и в ответах на `/today`, `/tm` и
`/raspisanie 13.10`, но в `state.json` не попадает — иначе новое задание
выглядело бы как «расписание изменили» и рассылка ушла бы повторно.

### Где хранятся записи

В файле `homework.json` в этом репозитории. Вечерняя рассылка читает его
при checkout, а вебхук на Vercel пишет туда через GitHub API — своего диска
у него нет. Для записи нужны ещё две переменные в настройках Vercel:

| Name | Value |
|---|---|
| `GITHUB_TOKEN` | fine-grained токен с правом Contents: Read and write на этот репозиторий |
| `GITHUB_REPO` | `nikikost29-alt/raspisanie-bot` (можно не задавать, это значение по умолчанию) |

Токен берётся в GitHub: **Settings → Developer settings → Personal access
tokens → Fine-grained tokens → Generate new token**, доступ только к этому
репозиторию, в Repository permissions поставить **Contents: Read and write**.

Без токена команды расписания работают как обычно, а на «дз!» бот честно
ответит, что записать не смог.

## Запустить вручную

Вкладка **Actions** → слева выбрать **Расписание на завтра** → кнопка
**Run workflow** → зелёная **Run workflow**.
Через полминуты появится запуск, по нему видно логи каждого шага.

Ручной запуск `daily.yml` идёт без `--last`.

Проверить у себя, ничего никому не отправляя:

```
.venv\Scripts\python.exe bot.py --dry
.venv\Scripts\python.exe bot.py --dry 05.09.26
```

## Если бот замолчал

Иди по списку сверху вниз, первое же несовпадение обычно и есть причина.

1. **Actions → последний запуск.** Красный крестик — открой лог упавшего шага,
   там будет текст ошибки. Заодно проверь личку: при любой ошибке бот пишет
   в `OWNER_ID`.
2. **Запуски вообще есть?** GitHub отключает крон в репозитории, где 60 дней
   не было активности, — приходит письмо. Лечится кнопкой **Enable workflow**
   на вкладке Actions или любым коммитом.
3. **Сообщение пришло один раз и больше не приходит.** Так и задумано: дата уже
   в `state.json`, повторно не шлётся. Если у ИС-41-23к поменяются **пары** —
   придёт версия с пометкой 🔄. Строка «данные на сайте» в сравнении не
   участвует: сайт обновляет её, когда меняется расписание любой группы.
4. **Хочешь заставить прислать заново** — удали нужную дату из `state.json`
   (или весь файл) и запусти воркфлоу вручную.
5. **`не задан BOT_TOKEN`** в логе — переменная не создана или названа иначе.
   Для рассылки смотри Settings → Secrets в GitHub, для команд — Settings →
   Environment Variables в Vercel.
6. **`Telegram отказал: Forbidden: bot was kicked`** — бота выкинули из группы,
   добавь обратно. **`chat not found`** — неверный `CHAT_ID`.
7. **`/raspisanie` не отвечает.** Проверь, что пишешь в группу из `CHAT_ID`
   или в личку с `OWNER_ID`. Дальше — вебхук: открой
   `https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo`, там видно адрес,
   число неотданных апдейтов и текст последней ошибки. Логи функции — в
   Vercel, вкладка проекта → Logs.
8. **Расписания нет на сайте.** Вечером придёт «⚠️ Расписание на завтра ещё не
   выложили». Это не поломка, это колледж не выложил файл.
9. **Сайт сменил вёрстку** — в логе будет `GroupNotFound` или «не удалось
   прочитать». Тогда чинить надо `parser.py`.
10. **«ReadTimeout … nf.uust.ru» в личке** — сайт колледжа не ответил за 30
    секунд. Рассылка сама пробует трижды с паузой, а за вечер проверяет
    сайт 4 раза, так что расписание обычно всё равно уходит. Это сообщение
    значит, что не вышло ни с одной из трёх попыток в этот раз.
11. **В клетке пары написано «Выходной день»** (или «День методической
    работы», «День самостоятельной работы») — бот покажет «пар нет,
    отдыхаем». Новую такую фразу дописывают в `DAY_OFF_RE` в `parser.py`.

## Заметки

- `getUpdates` больше не используется нигде: команды приходят вебхуком.
- Вебхук проверяет заголовок `X-Telegram-Bot-Api-Secret-Token` и всегда
  отвечает Telegram кодом 200 — иначе тот будет повторять доставку.
- Один и тот же `update_id` обрабатывается один раз (память в `/tmp`
  инстанса Vercel).
- Точка входа для Vercel — `app.py` в корне с переменной `app` (обычное
  WSGI-приложение) плюс `entrypoint` в `pyproject.toml`. Раскладка
  `api/*.py` с классом `handler` у Vercel считается легаси и на этом
  проекте не сработала.
- `state.json` коммитится обратно в репозиторий самим воркфлоу, с пометкой
  `[skip ci]`, чтобы этот коммит не запускал новые прогоны.
- Время дня считается по Asia/Yekaterinburg, а не по UTC, на котором работает
  GitHub.
