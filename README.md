# Бот с расписанием ИС-41-23к

Каждый вечер присылает в группу расписание на завтра с сайта НФ УУНиТ.
По команде `/raspisanie` показывает расписание в любой момент.
Рассылка живёт в GitHub Actions, команды — в вебхуке на Vercel.
Своего сервера не нужно.

| Файл | Что делает |
|---|---|
| `parser.py` | тянет расписание с сайта, отдаёт пары нужной группы |
| `bot.py` | собирает текст сообщения и отправляет в Telegram |
| `merge_state.py` | сливает `state.json`, если его пишут одновременно |
| `.github/workflows/daily.yml` | вечерняя рассылка |
| `api/telegram.py` | вебхук на Vercel: ответы на `/raspisanie` |
| `state.json` | что уже отправлено и на каком сообщении остановились |

## Секреты

Три значения нельзя класть в код — они лежат в настройках репозитория.

**Settings → Secrets and variables → Actions → New repository secret.** Три раза:

| Name | Secret |
|---|---|
| `BOT_TOKEN` | токен от @BotFather, вида `1234567890:AA...` |
| `CHAT_ID` | id группы, у супергрупп с минусом: `-100XXXXXXXXXX` |
| `OWNER_ID` | твой личный id — туда придут сообщения об ошибках |

Имена должны совпадать буква в букву, иначе бот скажет «не задан BOT_TOKEN».

Локально те же три значения лежат в `.env.local` рядом с `bot.py`. Этот файл
в `.gitignore` и на GitHub не уезжает — заполняешь его один раз у себя.

Если не знаешь `CHAT_ID`: добавь бота в группу, напиши там что угодно и открой
`https://api.telegram.org/bot<ТОКЕН>/getUpdates` — id будет в поле `chat.id`.

## Расписание запусков

`daily.yml` — в 13:20, 14:20, 15:20 и 16:20 UTC, то есть 18:20, 19:20, 20:20 и
21:20 по Уфе. Первый запуск, который увидит расписание, отправит его; остальные
промолчат. Последний запуск идёт с флагом `--last`: если расписание к вечеру так
и не выложили, он предупредит об этом и закроет день.

Команды живут **не в Actions, а в вебхуке на Vercel** (`api/telegram.py`).
Причина: GitHub не соблюдает крон `*/5` — по факту прогоны случались раз в
несколько часов, и `/raspisanie` висела неотвеченной. Вебхук Telegram зовёт
сразу, ответ приходит за секунду.

Вебхуку нужны те же `BOT_TOKEN`, `CHAT_ID`, `OWNER_ID` плюс `WEBHOOK_SECRET`
— их заводят в настройках проекта Vercel, а не в GitHub Secrets.

Команда работает только в группе из `CHAT_ID` и в личке с `OWNER_ID`,
остальные чаты бот игнорирует молча.

```
/raspisanie           до 19:00 — на сегодня, после — на завтра
/raspisanie сегодня
/raspisanie завтра
/raspisanie 05.09
```

## Запустить вручную

Вкладка **Actions** → слева выбрать **Расписание на завтра** → кнопка
**Run workflow** → зелёная **Run workflow**.
Через полминуты появится запуск, по нему видно логи каждого шага.

Ручной запуск `daily.yml` идёт без `--last`.

Проверить у себя, ничего никому не отправляя:

```
.venv\Scripts\python.exe bot.py --dry
.venv\Scripts\python.exe bot.py --dry 05.09.26
```

## Если бот замолчал

Иди по списку сверху вниз, первое же несовпадение обычно и есть причина.

1. **Actions → последний запуск.** Красный крестик — открой лог упавшего шага,
   там будет текст ошибки. Заодно проверь личку: при любой ошибке бот пишет
   в `OWNER_ID`.
2. **Запуски вообще есть?** GitHub отключает крон в репозитории, где 60 дней
   не было активности, — приходит письмо. Лечится кнопкой **Enable workflow**
   на вкладке Actions или любым коммитом.
3. **Сообщение пришло один раз и больше не приходит.** Так и задумано: дата уже
   в `state.json`, повторно тот же текст не шлётся. Если расписание на сайте
   изменят — придёт версия с пометкой 🔄.
4. **Хочешь заставить прислать заново** — удали нужную дату из `state.json`
   (или весь файл) и запусти воркфлоу вручную.
5. **`не задан BOT_TOKEN`** в логе — переменная не создана или названа иначе.
   Для рассылки смотри Settings → Secrets в GitHub, для команд — Settings →
   Environment Variables в Vercel.
6. **`Telegram отказал: Forbidden: bot was kicked`** — бота выкинули из группы,
   добавь обратно. **`chat not found`** — неверный `CHAT_ID`.
7. **`/raspisanie` не отвечает.** Проверь, что пишешь в группу из `CHAT_ID`
   или в личку с `OWNER_ID`. Дальше — вебхук: открой
   `https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo`, там видно адрес,
   число неотданных апдейтов и текст последней ошибки. Логи функции — в
   Vercel, вкладка проекта → Logs.
8. **Расписания нет на сайте.** Вечером придёт «⚠️ Расписание на завтра ещё не
   выложили». Это не поломка, это колледж не выложил файл.
9. **Сайт сменил вёрстку** — в логе будет `GroupNotFound` или «не удалось
   прочитать». Тогда чинить надо `parser.py`.

## Заметки

- `getUpdates` больше не используется нигде: команды приходят вебхуком.
- Вебхук проверяет заголовок `X-Telegram-Bot-Api-Secret-Token` и всегда
  отвечает Telegram кодом 200 — иначе тот будет повторять доставку.
- Один и тот же `update_id` обрабатывается один раз (память в `/tmp`
  инстанса Vercel).
- `state.json` коммитится обратно в репозиторий самим воркфлоу, с пометкой
  `[skip ci]`, чтобы этот коммит не запускал новые прогоны.
- Время дня считается по Asia/Yekaterinburg, а не по UTC, на котором работает
  GitHub.
