# Фаза 2 — подгруппы, кодировка, bot.py

**Запускал** (всё через `.venv\Scripts\python.exe`): `pip install -r requirements.txt` → 0; `bot.py --dry` на 02.09.26, 06.09.26, 10.09.26, 01.09.26 → все код 0; `bot.py --last 10.09.26` с пустым `.env.local` → код 1; `parser.py 02.09.26` (регрессия после правок) → код 0; два скрипта в scratchpad — юнит-проверки правок парсера и машины состояний с подменённым `send` (реальной отправки не было ни разу, `state.json` в проекте не появился).

`--dry 06.09.26` → `📅 ЗАВТРА, ВС 06.09 — пар нет, отдыхаем`; `--dry 10.09.26` → `⚠️ Расписание на завтра ещё не выложили (ЧТ 10.09)`; `--dry 01.09.26` → строка `2️⃣ 09:00–11:20 Тематический кураторский час Снетков А.В. ауд. 316` (явное «В 09:00» победило звонок 09:45 и убрано из текста); `--last` без секретов → `BotError: не задан CHAT_ID в .env.local`, не KeyError.

**Правки parser.py проверены синтетикой**: таблица с разными текстами в двух колонках группы вернула `{'num': 1, 'Матан подгр.1'}` и `{'num': 1, 'Физра подгр.2'}` двумя записями, а одинаковый текст в обеих колонках — одной; `fetch_timetable` с подменённым `_get` на utf-8-байтах вернул чистую кириллицу без «�», на cp1251-байтах — тоже, на мусоре бросил `ParserError`. Машина состояний: первый запуск отправил и записал дату; повтор с тем же текстом — 0 отправок; подменённый старый текст → сообщение начинается с `🔄 Расписание на завтра изменили`, а в state лёг текст без пометки; «нет расписания» без `--last` — 0 отправок и дата не отмечена, с `--last` — отправлено и отмечено, повторный `--last` молчит; `--dry` не тронул state.json. Часовой пояс: UTC 2026-09-03 22:04 против Екатеринбурга 2026-09-04 03:04, `tomorrow()` вернул 2026-09-05 — по UTC было бы 09-04.

**Не проверено**: реальная отправка в Telegram (по твоей просьбе не делал) — ветка `send()` целиком, включая ответ API и `parse_mode`; подгруппы и 8-я пара на живых данных сайта (там их сейчас нет, обе ветки прогнаны только на синтетике); фолбэк utf-8 на настоящем файле сайта; работа в GitHub Actions (переменные из `os.environ` без файла `.env.local`); `--last` при недоступном сайте.

**Отступление от ТЗ**: воскресенье не входит ни в один недельный файл, поэтому парсер на 06.09 возвращает `None` — формально это «не выложили». Чтобы получить ожидаемое «пар нет, отдыхаем», в `bot.build()` добавлено правило: `None` + воскресенье = выходной, `None` в любой другой день = «ещё не выложили». Если воскресенье вдруг появится в файле расписания, возьмутся реальные данные. Ещё: `bot.py` принимает необязательный аргумент-дату (нужен для `--dry`-проверок), а `requirements.txt` пополнен `python-dotenv` и `tzdata`.
